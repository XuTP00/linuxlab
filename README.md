# LinuxLab v0.02

Веб-сервис для практического изучения Linux «от нуля до Pro».
Курс построен вокруг практики: каждое задание выполняется в настоящем
docker-контейнере с Ubuntu и проверяется автоматически движком проверок.

| Показатель | Значение |
|------------|----------|
| Заданий | **188** в **14** модулях (2940 баллов) |
| Проверок | 425 автоматических проверок, 33 типа |
| Теория | блок «Теория» у каждого задания (~52 000 знаков) |
| Подсказки | 531 подсказка, 380 целей обучения |

## Возможности

* **Три рабочие вкладки** справа: настоящий bash-терминал, предпросмотр сайта
  и редактор кода в стиле VS Code.
* **Терминал — настоящий bash в PTY**: печатаете прямо в консоли, работают
  автодополнение по `Tab`, история (`↑/↓`), `Ctrl+C`, `nano`, `top`, `man`/`less`.
* **Вкладка Web** показывает сайт, который отдаёт веб-сервер ученика
  **внутри контейнера** (Angie на 8080, Apache на 80/8081/8082) — с полем порта,
  автообновлением и статусом ответа.
* **Вкладка IDE** — редактор кода в стиле VS Code: проводник файлов контейнера,
  подсветка синтаксиса, вкладки файлов, создание/переименование/удаление,
  сохранение по `Ctrl+S` и терминал внизу.
* **Условия заданий нельзя скопировать** — команды приходится вводить руками.
  Разблокировка — по паролю администратора.
* **Прогресс** сохраняется в SQLite и показывается наверху.

## Быстрый старт

Скопируйте проект на сервер и запустите установщик — он сам поставит зависимости,
соберёт образ, настроит systemd и nginx и проверит, что всё работает:

```bash
sudo bash install.sh
```

Поддерживаются **Debian/Ubuntu, RHEL/CentOS/Rocky/Alma/Fedora, Arch, openSUSE**
(Alpine — без systemd, сервис запускается вручную).

Установщик:

1. определяет дистрибутив и ставит `docker`, `nginx`, `python3`, `python3-venv`;
2. разворачивает код в `/opt/linuxlab`, создаёт venv и ставит зависимости
   (fastapi, uvicorn);
3. собирает docker-образ лаборатории `linuxlab/lab:latest`
   (Ubuntu 26.04 + sshd + cron + утилиты + готовый проект для IDE);
4. создаёт systemd-юнит `linuxlab` и включает автозапуск;
5. настраивает nginx (reverse proxy + WebSocket + статика), убирает дефолтный сайт;
6. выполняет самопроверку: наличие файлов интерфейса (включая редактор CodeMirror),
   импорт учебного контента, готовность образа и ответы API — и печатает адрес.

```bash
sudo bash install.sh --uninstall        # снести сервис (данные и образ останутся)
sudo bash install.sh --skip-packages    # не трогать системные пакеты
APP_DIR=/srv/linuxlab DATA_DIR=/srv/linuxlab-data HTTP_PORT=8080 sudo bash install.sh
```

Обновление после правки кода — тот же скрипт:

```bash
cd /opt/linuxlab && sudo bash install.sh
```

## Как это устроено

```
Браузер ──nginx(:80)──► FastAPI/uvicorn(:8080) ──docker exec──► контейнер ученика
   │                          │                                     │
   │ WebSocket /ws/{sid}      │ проверки заданий                    │ bash в PTY,
   │                          │ (docker exec от root)               │ sshd, cron,
   ▼                          ▼                                     │ веб-серверы
 xterm.js / CodeMirror    SQLite: прогресс                        ▼
                                                            linuxlab-sess-<id>
```

* Один контейнер на пользователя: `linuxlab-sess-<id>`, в нём пользователь
  `student` с `sudo` без пароля, sshd и cron.
* Внутри — `bash --rcfile /etc/lab.bashrc -i` под PTY (`script`), поэтому
  доступны интерактивные программы и `Ctrl+C`.
* Команды идут по WebSocket `/ws/{sid}`, вывод стримится в xterm.js.
* Проверки выполняются отдельным `docker exec` внутри того же контейнера.
* Простаивающие сессии удаляются через 30 минут.

## Три вкладки

### `>_ Terminal`

Настоящий bash в PTY: `Tab` дополняет, `↑/↓` — история, `Ctrl+C` прерывает,
`Ctrl+L` очищает. Работают `nano`, `top`, `man`/`less`, `vim`.

### `🌐 Web <порт>`

Встроенный браузер с превью сайта, который отдаёт веб-сервер ученика **внутри
контейнера**. Порт выбирается прямо в панели (по умолчанию 8080 — Angie),
путь — отдельным полем. Есть кнопка «Обновить», автообновление и строка статуса
(`200 OK · text/html`). Если сервер не запущен — понятная страница-подсказка.

Запрос идёт через `GET /api/web/{sid}/proxy/{port}/{path}`: backend обращается
к контейнеру и отдаёт страницу, подставляя `<base>`, поэтому относительные
ссылки (CSS, картинки) тоже работают.

### `🧩 IDE`

Редактор кода в стиле VS Code:

* **проводник** файлов контейнера (`/home/student`) с размерами, кнопками
  «новый файл / новая папка / обновить», правым кликом — переименовать/удалить;
* **меню** (Файл, Правка, Выделение, Вид, Переход, Запуск) и статус сохранения;
* **вкладки файлов** и редактор CodeMirror с подсветкой синтаксиса
  (Python, HTML, JS, CSS, Shell, SQL, nginx, Dockerfile, YAML, Go, Rust и др.),
  нумерацией строк и `Tab`-отступами; `Ctrl+S` — сохранить в контейнер,
  `Ctrl+Enter` — запустить;
* **снизу панель** как в VS Code: ПРОБЛЕМЫ / ВЫВОД / ОТЛАДКА / **ТЕРМИНАЛ** / ПОРТЫ,
  где живёт тот же bash — он физически переезжает между вкладками Terminal и IDE.

В образе есть готовый проект `~/project` (`index.html`, `style.css`, `about.html`,
`app.py`, `README.md`) — его можно сразу отдать веб-серверу
(`cd ~/project && python3 -m http.server 8080`) и увидеть во вкладке Web.

## Защита от копирования условий

Текст заданий нельзя выделить мышью, скопировать `Ctrl+C`/`Ctrl+X`/`Ctrl+A`,
вызвать контекстное меню или вывести на печать — вместо этого показывается
подсказка. Терминал при этом работает как обычно.

Кнопка «🔒 вводите вручную» в шапке панели заданий открывает запрос пароля
администратора: с правильным паролем копирование разрешается на 8 часов
(состояние хранится на сервере, у каждого браузера своё), с неправильным —
остаётся заблокированным. Повторное нажатие снова блокирует.

Пароль задаётся переменной `LINUXLAB_ADMIN_PASSWORD` (по умолчанию `1541685`),
время жизни — `LINUXLAB_UNLOCK_TTL` (по умолчанию 28800 секунд).

## Учебный курс

Курс построен так, чтобы новичок не спотыкался о незнакомые конструкции:
в первых трёх модулях **нет ни одного перенаправления** (`>`, `>>`, `|`) —
только сам терминал и базовые команды. Перенаправления вынесены в отдельную
подробную тему (модуль 3).

| # | Модуль | Заданий | О чём |
|---|--------|---------|-------|

| 1 | Терминал и навигация | 13 | pwd, ls, cd, mkdir, nano, cp, mv, rm, glob, find |
| 2 | Файлы, каталоги и права | 14 | chmod, umask, chown, ссылки, du/df, tar |
| 3 | Перенаправления и пайпы | 22 | `>`, `>>`, `<`, `|`, `2>`, `2>&1`, /dev/null, tee, heredoc, `$(...)`, xargs, pipefail |
| 4 | Текст: grep, sed, awk | 15 | поиск, замена, поля, инструменты в пайпах |
| 5 | Поиск, архивы и хеши | 12 | find, tar, gzip, rsync, sha256sum, diff |
| 6 | Процессы и фоновые задачи | 13 | ps, top, kill, jobs, nohup, /proc, nice |
| 7 | Пользователи, группы, sudo | 12 | useradd, groupadd, usermod, su, /etc/passwd |
| 8 | Сеть, DNS и SSH | 12 | ip, ping, curl, wget, ss, /etc/hosts, ssh-ключи, scp |

Последние два модуля — про веб-серверы: задания проверяются **по HTTP**
(сайт должен реально отвечать), а результат сразу видно во вкладке Web.

К каждому заданию добавлен блок «Теория»: что делает команда, какие у неё ключи
и на что обратить внимание.

## Движок проверок

33 типа проверок — от «файл существует» и «в файле ровно N строк» до
«процесс запущен», «порт слушается», «в выводе терминала есть строка»
и «задание cron содержит расписание»:

`file_exists`, `file_absent`, `file_contains`, `file_not_contains`, `file_matches`,
`file_lines`, `file_nonempty`, `file_empty`, `file_exists_wait`, `dir_exists`,
`dir_contains`, `file_count`, `file_mode`, `file_owner`, `symlink`, `cmd_ok`,
`cmd_fail`, `cmd_stdout_contains`, `cmd_stdout_not_contains`, `cmd_stdout_matches`,
`cmd_stdout_equals`, `user_exists`, `group_exists`, `user_in_group`, `cron_contains`,
`history_contains`, `output_contains`, `output_matches`, `output_not_contains`,
`file_size_min`, `proc_running`, `proc_not_running`, `port_listening`,
`file_exists_in_path`.

## API

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/curriculum` | модули и задания с прогрессом |
| GET | `/api/task/{id}` | текст задания, теория, цели, подсказки, список проверок |
| GET | `/api/solution/{id}` | эталонное решение |
| POST | `/api/check` | проверка задания в контейнере |
| POST | `/api/session` | создать контейнер-сессию |
| POST | `/api/session/{id}/exec` | выполнить команду (REST-фолбэк) |
| POST | `/api/session/{id}/reset` | пересоздать контейнер |
| WS | `/ws/{sid}` | поток вывода терминала |
| GET/POST | `/api/progress` | прогресс и его сброс |
| GET/POST | `/api/protection` | состояние и разблокировка копирования |
| GET | `/api/web/{sid}/proxy/{port}/{path}` | страница с веб-сервера ученика (вкладка Web) |
| GET | `/api/web/{sid}/status?port=` | отвечает ли веб-сервер в контейнере |
| GET | `/api/ide/{sid}/tree` | дерево файлов ученика для IDE |
| GET | `/api/ide/{sid}/file?path=` | содержимое файла |

## Структура проекта

```
install.sh            — установщик для любого Linux-дистрибутива (одна команда)
app/
  main.py             — FastAPI: API, WebSocket терминала, проверки, IDE, предпросмотр сайта
  sessions.py         — менеджер docker-контейнеров и интерактивных bash-сессий (PTY)
  checker.py          — движок проверок (33 типа)
  progress.py         — прогресс пользователя (SQLite) и разблокировка копирования
  config.py           — пути, порты, параметры окружения
  curriculum/         — учебный контент: 14 модулей, 188 заданий, теория к каждому
    m00_help.py … m13_apache.py
    theory_1.py … theory_5.py — пояснения к заданиям
  static/
    index.html        — интерфейс (панель заданий + терминал/Web/IDE)
    css/app.css, css/ide.css — тёмная тема и стиль IDE
    js/app.js         — логика интерфейса (терминал, Web, IDE, проверки)
    vendor/           — xterm.js и CodeMirror 5 с 17 режимами подсветки синтаксиса
deploy/
  Dockerfile.lab      — образ контейнера-лаборатории (Ubuntu 26.04 + sshd + cron + проект)
  entrypoint.sh      — точка входа контейнера: sshd, cron, sleep infinity
  linuxlab.service   — systemd unit (шаблон; установщик генерирует свой)
  nginx.conf         — конфигурация nginx (шаблон)
  install.sh         — обёртка на ../install.sh
  validate_course.py — автопрогон эталонных решений всех заданий (тест контента)
```

## Проверка качества контента

```bash
cd /opt/linuxlab && ./venv/bin/python deploy/validate_course.py
```

Скрипт выполняет эталонное решение каждого задания в чистом контейнере
и прогоняет все проверки — итог должен быть «188 из 188».

## Обслуживание

```bash
systemctl status linuxlab        # статус сервиса
journalctl -u linuxlab -f         # логи сервиса
systemctl restart linuxlab        # перезапуск
docker ps                         # активные контейнеры-сессии
docker image ls linuxlab/lab      # образ лаборатории
curl -s http://127.0.0.1:8080/api/health
```

Ручная установка (если скрипт не подходит) — по шаблонам в `deploy/`:
`Dockerfile.lab`, `nginx.conf`, `linuxlab.service`.
